1. Java

JMeter corre sobre Java. Para saber si ya está instalado y qué versión es:

java -version

Si el comando no existe, en macOS lo instala Homebrew junto con JMeter en el paso 2. En Windows y Linux se instala un JDK, por ejemplo Eclipse Temurin 21. Una terminal abierta antes de instalarlo no ve el comando java hasta reabrirla.

2. JMeter

macOS, con Homebrew

brew install jmeter
jmeter --version

Homebrew instala también Java 21 y el Plugins Manager. El comando jmeter abre la interfaz gráfica.

Windows

  1. Descargar apache-jmeter-5.6.3.zip de la sección Binaries en la página de descargas.
  2. Descomprimirlo en una ruta sin espacios, por ejemplo C:\apache-jmeter-5.6.3.
  3. Abrir la interfaz con bin\jmeter.bat.

Con Scoop o Chocolatey también se instala la 5.6.3:

scoop bucket add extras
scoop install extras/jmeter
choco install jmeter

Linux

curl -LO https://archive.apache.org/dist/jmeter/binaries/apache-jmeter-5.6.3.tgz
tar -xzf apache-jmeter-5.6.3.tgz -C ~
~/apache-jmeter-5.6.3/bin/jmeter

Dónde queda la carpeta de JMeter

La carpeta de JMeter es la que contiene bin/ y lib/. Los plugins van en lib/ext/, dentro de ella. La ruta depende de cómo se instaló:

InstalaciónCarpeta lib/ext
Homebrew, Mac con Apple Silicon (M1 en adelante)/opt/homebrew/opt/jmeter/libexec/lib/ext
Homebrew, Mac con Intel/usr/local/opt/jmeter/libexec/lib/ext
Homebrew en Linux/home/linuxbrew/.linuxbrew/opt/jmeter/libexec/lib/ext
ZIP de Apache en WindowsC:\apache-jmeter-5.6.3\lib\ext, o donde se haya descomprimido
Scoop%USERPROFILE%\scoop\apps\jmeter\current\lib\ext
ChocolateyC:\ProgramData\chocolatey\lib\jmeter\tools\apache-jmeter-5.6.3\lib\ext
TGZ de Apache en macOS o Linux~/apache-jmeter-5.6.3/lib/ext, o donde se haya descomprimido

Con Homebrew, este comando imprime la ruta en cualquier máquina:

echo "$(brew --prefix jmeter)/libexec/lib/ext"

3. Plugins Manager

Con JMeter abierto, el menú Options tiene una entrada Plugins Manager si el manager ya está instalado. Homebrew lo trae; el ZIP, el TGZ, Scoop y Chocolatey no.

Si la entrada no aparece, se descarga el jar a la carpeta lib/ext de la tabla anterior, con JMeter cerrado. El enlace jmeter-plugins.org/get/ siempre entrega la versión más reciente.

macOS o Linux, TGZ

curl -L -o ~/apache-jmeter-5.6.3/lib/ext/jmeter-plugins-manager.jar https://jmeter-plugins.org/get/

Windows, PowerShell

Invoke-WebRequest -Uri https://jmeter-plugins.org/get/ -OutFile C:\apache-jmeter-5.6.3\lib\ext\jmeter-plugins-manager.jar

Si JMeter quedó en otra carpeta, se cambia la ruta del comando por la de la tabla. Al abrir JMeter otra vez, el menú Options ya muestra Plugins Manager.

4. Custom Thread Groups y 3 Basic Graphs

  1. Abrir Options > Plugins Manager.
  2. En la pestaña Available Plugins, buscar Custom Thread Groups y marcar su casilla.
  3. Buscar 3 Basic Graphs y marcar su casilla.
  4. Presionar Apply Changes and Restart JMeter. JMeter descarga los dos plugins y sus dependencias, y se reinicia solo.
  5. Abrir el Plugins Manager otra vez. Los dos plugins aparecen en la pestaña Installed Plugins. Esa pestaña es la captura que va en evidencia/plugins.png.

5. Comprobar con la plantilla

El repositorio trae plantilla.jmx, un plan con un Concurrency Thread Group y un GET /books. Abrirla en JMeter, con File > Open, es la prueba de que Custom Thread Groups quedó instalado: sin el plugin, JMeter no carga el plan y muestra un error que menciona ConcurrencyThreadGroup.

Con el API corriendo (uv run api.py en la raíz del repositorio), el botón verde de JMeter corre la plantilla y el Summary Report se llena con solicitudes a /books y ninguna falla.

La plantilla se guarda como plan.jmx y se completa con lo que pide la sección 2. El plan del README. Las cantidades de usuarios, ramp-up y tiempo sostenido que trae están escritas a mano, y el README pide poder cambiarlas desde la línea de comandos.
